# fix: Quarantine Rollback on Failed From-Scratch Runs

If `verify --from-scratch` runs and the pipeline exits non-zero, artifacts stay quarantined
and the project is left in a broken state. This is a correctness hole: the tool moved files
and then abandoned them on failure. This fix adds automatic rollback on pipeline failure,
cleanup on success, and a `restore-quarantine` command for manual recovery.

## Acceptance Criteria

- [ ] When `verify --from-scratch` pipeline exits non-zero, all quarantined artifacts are
  automatically restored to their original locations before `verify_project` returns.
- [ ] Before restoring, any files already regenerated by the failed pipeline are deleted
  (prevents partial/corrupt outputs mixing with restored originals).
- [ ] When `verify --from-scratch` pipeline exits zero (success), the quarantine directory
  is deleted.
- [ ] `VerifyResult` gains a `rolled_back: bool` field. CLI prints
  `Pipeline failed — artifacts restored from quarantine.` when `rolled_back` is True.
- [ ] `verify --from-scratch --no-rollback` skips automatic rollback. CLI prints:
  `Warning: rollback disabled. Project may be left in a broken state on pipeline failure.`
- [ ] `econharness restore-quarantine [--path .] [--quarantine-dir <timestamp>]` restores
  artifacts from a specific quarantine directory and deletes the quarantine dir after success.
- [ ] If `--quarantine-dir` is omitted, `restore-quarantine` lists available quarantine
  directories under `.econharness/quarantine/` by timestamp and exits with a message asking
  the user to specify one.
- [ ] Rollback does not affect `verify` runs without `--from-scratch` (no quarantine involved).
- [ ] Tests: verify rollback on non-zero exit; verify cleanup on zero exit; verify
  `--no-rollback` leaves broken state; verify `restore-quarantine` command.

## Context

**`quarantine_generated_artifacts` (quarantine.py:17-52):**
- Moves files from `derived/`, `output/`, `temp/` to `.econharness/quarantine/<timestamp>/`
- After moving each root's children, recreates the empty root dir (line 49: `root_path.mkdir`)
- Returns `QuarantineResult(quarantine_dir, moved_paths)` — the manifest needed for restore

**`verify_project` (verify.py:39-90):**
- Calls `quarantine_generated_artifacts` at line 55, stores result
- Runs pipeline subprocess at line 59 with `check=False` (never raises on non-zero)
- Computes `regenerated_paths` and `missing_paths` at lines 67-72
- Returns `VerifyResult` — currently does nothing on failure

**Rollback logic:**
- Restore = inverse of quarantine: move files from `.econharness/quarantine/<timestamp>/`
  back to their original paths under `project_root`
- Before restoring: delete any `path` in `regenerated_paths` (already exists at original
  location from failed partial build)
- The empty root dirs still exist (line 49 recreated them) — moving files back into them
  works without special directory recreation
- After restoring: optionally delete the now-empty quarantine dir

**`--no-rollback` note:** Intended for debugging partial outputs. Does not affect the
`moved_paths` / `regenerated_paths` tracking in `VerifyResult`.

## Implementation Notes

### Files to change
- `econharness/quarantine.py` — add `restore_quarantine(quarantine_result, project_root)`
  function; add `delete_quarantine_dir(quarantine_dir)` helper
- `econharness/verify.py` — call rollback/cleanup after subprocess; add `--no-rollback`
  to `verify_project` signature; add `rolled_back` to `VerifyResult`
- `econharness/cli.py` — add `--no-rollback` flag to `verify` subparser; print
  `rolled_back` message; add `restore-quarantine` subcommand
